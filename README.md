# Уникализатор видео

Десктопное приложение для пакетной уникализации видео под TikTok / Reels / Shorts.
Кидаете ролик, отмечаете нужные параметры, ставите количество копий — программа
делает N разных файлов: для алгоритмов они различаются (битрейт, кодек, частота
кадров, геометрия, шум, метаданные), для зрителя выглядят одинаково.

## Запуск

```
pip install -r requirements.txt
python main.py
```

Или двойным кликом по `Запустить.bat`.

## FFmpeg

Вся обработка идёт через FFmpeg — он должен быть установлен:

```
winget install Gyan.FFmpeg
```

После установки перезапустите терминал (нужен обновлённый PATH). Альтернатива —
положить `ffmpeg.exe` и `ffprobe.exe` в папку `ffmpeg\bin` рядом с `main.py`:
приложение проверит и её. Статус («FFmpeg: найден / НЕ НАЙДЕН») виден в правом
верхнем углу окна.

## Как пользоваться

1. **Исходные видео** — «Добавить файлы», «Добавить папку» или перетаскивание
   мышью прямо в список. Можно закинуть сразу несколько роликов.
2. **Папка результата** — например `C:\Users\User\Downloads\output`.
   Создаётся автоматически, если её нет.
3. **Параметры** — отметьте галочками то, что нужно менять, и задайте диапазон
   min/max. Для каждой копии значение выбирается случайно внутри диапазона.
4. **Копий на видео** — сколько разных файлов сделать из каждого исходника.
5. **Сгенерировать копии.** Прогресс и лог видны внизу; «Стоп» прерывает пачку.

Результат: `<имя исходника>_uq01.mp4`, `_uq02.mp4` и так далее.

## Пресеты

В выпадающем списке четыре встроенных набора:

| Пресет | Что делает |
|---|---|
| Мягкий | Только тон, шум, кодек и метаданные — визуально не отличить |
| Средний | + скорость, зум, кроп, сдвиг пикселей, сдвиг тона аудио |
| Жёсткий | + поворот, виньетка, дисторсия, обрезка начала/конца, случайный размер |
| Только метаданные и кодек | Перекодирование без изменения картинки |

Свои наборы сохраняются кнопкой «Сохранить пресет» в `presets.json` рядом с
приложением и помечаются звёздочкой ★.

## Режим обработки

Внизу окна один список «Режим» — он заменяет ручной выбор кодека, качества и
нагрузки на процессор. На **картинку режим почти не влияет**, влияет на скорость,
размер файла и загрузку компьютера. Уникализацию делают фильтры (яркость, шум,
кроп), а не режим.

| Режим | Что происходит | Когда брать |
|---|---|---|
| **Быстро** | кодирует видеокарта, процессор почти свободен | по умолчанию: самый быстрый вариант |
| **Качество** | кодирует процессор (`libx264`, preset `medium`) | файл компактнее при той же картинке; когда не жалко времени |
| **Фоновый** | `libx264` `veryfast`, половина ядер, пониженный приоритет | когда нужно параллельно работать за компьютером |

Кодек в режиме «Быстро» подбирается сам: при запуске приложение проверяет
`h264_mf` (встроенный в Windows путь к кодировщику видеокарты — работает на
NVIDIA, AMD и встроенной графике Intel), затем `h264_nvenc`, `h264_qsv`,
`h264_amf`. Что именно выбрано, написано серым справа от списка («видеокарта,
h264_mf») и в логе. Если аппаратного кодировщика нет или отвалился драйвер,
программа молча переключается на процессор — надпись меняется на «видеокарта
недоступна — процессор».

### Если сильно грузится процессор

Замер на i3-12100F + RTX 3050, ролик 1080×1920 / 30 с, полный набор фильтров:

| Вариант | Время | Потрачено CPU-времени |
|---|---|---|
| `libx264` veryfast | 9.5 с | 48.0 с |
| `h264_mf` | 4.7 с | 11.1 с |
| `h264_mf`, только перекодирование без фильтров | 4.6 с | 7.5 с |

То есть кодек забирает себе бóльшую часть нагрузки: переход на `h264_mf`
уменьшает работу процессора примерно вчетверо.

**Полностью перенести обработку на видеокарту нельзя.** На GPU уходит только
сжатие. Фильтры (`eq`, `noise`, `rotate`, `lenscorrection`, `vignette`) в FFmpeg
существуют лишь в программном виде — CUDA-версий у них нет, поэтому их всегда
считает процессор. Но, как видно из таблицы, на фильтры приходится всего
11.1 − 7.5 ≈ 3.6 с из 11.1 с; основное — декодирование и преобразование цвета.

Что можно сделать дополнительно:

- переключить режим на **Фоновый** — половина ядер и пониженный приоритет
  FFmpeg: обработка идёт дольше, зато компьютером можно пользоваться;
- снять галочки с самых тяжёлых фильтров — `Noise`, `Blurred Border`,
  `Lens Correction`, `Rotation`;
- не задирать `Dimensions` выше 1080×1920 — TikTok больше не покажет.

## Практические советы

- **Держите диапазоны узкими.** Контраст 1.1–1.5 из примера — это уже заметно
  глазу; для «незаметной» уникализации ставьте 1.02–1.06, яркость 0.01–0.03,
  насыщенность 0.96–1.0.
- **Flip меняет картинку сильно** — текст и лица в кадре зеркалятся. Включайте
  только если в ролике нет надписей.
- **Скорость выше 1.1** слышна по голосу. 1.02–1.05 безопаснее.
- **Blurred Border и Random Pixel Size** сильнее всего меняют перцептивный хеш,
  но и заметнее всего для зрителя — комбинируйте осознанно.
- **Режим** оставляйте на «Быстро» — качество копий от него почти не зависит,
  а времени уходит вдвое меньше.
- Каждая копия логируется со своим набором значений — лог открывается кнопкой
  «Показать лог», по нему легко понять, что именно применилось.

## Структура проекта

```
main.py                 точка входа
core/
  config.py             декларативное описание 25 параметров
  ffmpeg_utils.py       поиск ffmpeg/ffprobe, чтение свойств файла
  pipeline.py           сборка команды ffmpeg (чистая функция, без запуска)
  worker.py             фоновый поток уникализации
  presets.py            встроенные и пользовательские пресеты
  theme.py              тёмная тема (Qt Style Sheets)
  ui.py                 интерфейс
presets.json            создаётся при первом сохранении своего пресета
input/                  исходные ролики
output/                 готовые копии (папку можно сменить в программе)
ffmpeg/bin/             сюда можно положить ffmpeg.exe и ffprobe.exe
```

Добавить новый параметр: описать его в `config.py` и обработать в
`pipeline.build_job` — интерфейс соберётся сам.
